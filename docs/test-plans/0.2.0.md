# 0.2.0 test plan

Every feature lands through `mix ci` (compile -Werror, format, credo --strict,
dialyzer, tsc, full suite, installer suite) — that is table stakes, not this
plan. This plan is what 0.2.0 adds **on top**: the cross-feature sweeps, the
visual passes, and the mobile bar, each executed against real sites
(`demo/site` and `example/`) before the release PR.

Legend: each item is checked off with a link or note in the release PR body.

## 1. Styling ladder (tokens + custom.css + @layer)

Automated (in-suite):
- [ ] `tokens:` overrides land in every page head, 404 included (`styling_ladder_test`)
- [ ] unknown token fails the build naming the nearest real one
- [ ] values carrying `<>{};` rejected at load (style-injection guard)
- [ ] `assets/custom.css` ships and links after the tokens block, base_path-aware
- [ ] both official themes' CSS wrapped in `@layer theme` (gate)
- [ ] `cherry config tokens.NAME VALUE` writes surgically, validates the name
      against the manifest, rolls back rejected values (`config_test`)
- [ ] `cherry theme.tokens` envelope covered (`json_envelope_test`)

Manual sweep (CLI only, against a scratch copy of demo/site):
- [ ] `cherry theme.tokens` → `config tokens.--color-accent "#7c3aed"` →
      `build` → grep the emitted head → serve and confirm links are violet
- [ ] override + custom.css together: custom.css wins where both touch the
      same declaration
- [ ] `config tokens.--color-acent` (typo) exits 2 and names `--color-accent`

Visual:
- [ ] demo/site with violet accent: links, hover, selection, code keywords all
      follow, in both renditions

## 2. light-dark() migration

Automated:
- [ ] token-count gate updated: every paired token = 1 fallback + 1
      `light-dark()` line; print-overridden +1; fonts/measure 1
- [ ] both themes parse (build succeeds, goldens byte-stable across a double
      build)
- [ ] toggle forces either rendition via `color-scheme` alone

Visual:
- [ ] light/dark/auto × default/cherrybomb on a post page: no color
      regressions against pre-migration screenshots
- [ ] fallback check: with `light-dark()` support disabled (devtools or an old
      engine), the site reads as the complete light rendition — never broken
      colors
- [ ] print preview of a post and the CV: forced-light, as before

## 3. Content components (figure / video / callout)

Automated:
- [ ] each component renders its documented markup from a fixture post
- [ ] schema-validated args: missing required attr → check diagnostic naming
      file and component; unknown component name → diagnostic, source text
      left visible in output (never silently swallowed)
- [ ] output styled by tokens only (color-literal gate covers the new CSS)
- [ ] theme swap: the same post renders correctly under both official themes

Manual:
- [ ] a video embed carries no third-party requests at page load
      (privacy-preserving facade; click to load)

Visual:
- [ ] figure with caption, video facade, callout with custom title — both
      themes, both renditions, 390px and desktop

## 4. HEEx template lane

Automated:
- [ ] runtime HEEx render inside `mix release` assembly (the spike's
      REL-SPIKE-PASS as a test)
- [ ] a `.html.heex` template wins over `.html.eex` at the same lookup level;
      resolution chain printable via `theme.which`
- [ ] function components: declared props enforced, slot content renders,
      HTML-aware escaping on by default
- [ ] malformed template → error with file, line:column, and caret via
      `cherry check`
- [ ] eject/diff/provenance work identically for `.heex` overlays

Manual:
- [ ] convert one demo/site overlay to HEEx and run the full authoring loop
      from the CLI alone

## 5. Mobile bar (both themes, out of the box)

Viewports: 360×800, 390×844, 768×1024 — light and dark each.

- [ ] no horizontal body scroll on: home, post with code + table + footnotes,
      blog index, tag page, portfolio timeline, CV, 404, search results open
- [ ] tap targets ≥ 44×44 CSS px: nav links, theme toggle, copy button,
      search input, pagination
- [ ] code blocks scroll internally; tables scroll inside `.table-scroll`
- [ ] search drawer usable at 360px (input full width, results within
      viewport, dismissible)
- [ ] font size never below 16px effective for body text; no iOS zoom on
      focusing the search input
- [ ] portfolio timeline and CV readable at 360px (no truncated dates or
      overlapping columns)
- [ ] `theme-toggle` reachable and functional on touch
- [ ] 404 page centered and readable

## 6. End-to-end release sweep (repeat of the 0.1.0 discipline)

- [ ] 16-verb CLI sweep against a fresh `mix cherry.new` site — every verb,
      `--json` and human, exit codes checked
- [ ] `demo/GUIDE.md` outputs re-verified against the built CLI (guide gate
      keeps the verb list honest; the version-bearing outputs need eyes)
- [ ] double-build byte-identical on demo/site and example/
- [ ] `cherry check --strict` exits 0 on demo/site and example/
- [ ] serve + edit loop: token override written by `cherry config` triggers a
      rebuild and the browser reloads with the new accent
- [ ] screenshot matrix archived in the release PR: {default, cherrybomb} ×
      {light, dark} × {desktop 1280, mobile 390} × {home, post, blog index,
      portfolio, CV, 404}
